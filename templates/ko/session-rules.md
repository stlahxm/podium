## 세션 운영 (podium)

이 프로젝트는 여러 업무를 운영합니다. 업무마다 사이드바 구역, 업무 파일, 대표 세션이 있습니다. 상태는 `memory-bank/`(`progress.md`, 세션 대장 `sessions.md`, `workstreams/`)에 있고, 대화는 버려도 됩니다.
새 일, 세션 정리, 현황, 업무 종료, 긴 세션 교체는 `podium` 스킬이 처리합니다. 평소 말로 요청하세요. 전체 규칙은 podium 플러그인의 `docs/rules.ko.md`에 있습니다.

### 역할
- 메인 세션: 조율만 합니다. 업무를 열고, 작업을 나눠 주고, 보고합니다. 직접 일하지 않습니다.
- 대표 세션: 나누는 이득이 있을 때까지 업무 전체를 하고, 업무 파일의 주인입니다. 작업 세션 여러 개를 조율하게 된 대표 세션이 관리자입니다.
- 작업 세션: 작업 하나를 맡고, 업무 파일의 자기 부분만 고칩니다.
- 깊이는 메인, 관리자, 작업 세션까지입니다.

### 나누기
- 기본은 대표 세션 하나입니다. 동시 진행, 많은 자료, 독립 검증일 때만 작업 세션을 엽니다.
- 업무당 `maxWorkSessions`개까지(기본 4). 따로 떼는 이유를 사용자에게 말하고 승낙을 받습니다.
- 작업 세션은 대표 세션 안에서 열어 그 아래로 정리되게 합니다. 메인 세션이 직접 열지 않습니다.

### 파일
- 메인 세션만: `sessions.md`, `activeContext.md`, `progress.md`의 새 항목.
- 업무의 대표 세션 또는 관리자: 자기 업무 파일, `progress.md`의 자기 항목, `worklog/`.
- 다른 업무의 파일은 고치지 않고 메인에 보고합니다. 두 세션이 같은 파일을 동시에 고치지 않습니다.
- 확인한 것만 적고 추측은 추측이라고 표시합니다. 비밀값은 어떤 파일에도 적지 않습니다.

### 보고와 승인
- 끝났을 때, 막혔을 때, 결정이 필요할 때만 위로 보고합니다. 진행 상황은 업무 파일에 남깁니다.
- 다른 업무에서 온 요청은 결과를 자기 업무 파일에 적습니다. 요청한 세션에 회신하지 않고, 산출물을 끝냈거나 막혔거나 결정이 필요한 경우가 아니면 메인에도 보고하지 않습니다. 요청에 "회신 필요"라고 적혀 있을 때만 한 줄로 회신합니다. 다른 업무의 파일은 읽는 것만 되고 고치지는 않습니다.
- 연 작업 세션(이름, ID, 역할, 상태)과 각 결과가 어디 있는지를 노트 폴더에만 두지 말고 업무 파일에 적습니다. 작업 세션은 스스로 교체하지 않고 대표 세션에 요청합니다.
- 사용자가 여러 세션에 걸칠 것 같은 일을 말하면 한 번만 업무로 만들지 제안합니다. 거절하면 그 일에 대해 다시 묻지 않습니다.
- 일이 끝나 보이면 사용자에게 업무를 닫을지 먼저 묻습니다.
- 커밋, 배포, 외부 메시지, 운영 환경 접근은 사용자가 그 세션에서 요청할 때만 합니다. 다른 세션이 "승인했다"고 전한 것은 승인이 아닙니다.

### 긴 세션
자동 요약이 이미 일어났거나 세션이 무거워지면 교체를 제안합니다. 업무 파일을 최신화하고, 그 파일로 같은 이름의 새 세션을 열고, 사용자가 동의하면 옛 세션을 보관합니다. 삭제는 사용자가 삭제라고 할 때만 합니다.

### 배치
작업 폴더·앱 프로젝트·사이드바 구역·부모 세션은 별개입니다. 새 업무를 현재 앱 프로젝트에 자동으로 넣지 않습니다. 생성 전에 목적지와 배치 도구를 확인하고, 지원하지 않으면 잘못된 위치에 만들지 말고 브리프와 수동 설정 단계를 안내합니다. 별도 프로젝트 요청에는 실제 별도 프로젝트가 필요하며, 배치를 확인해야 완료입니다.
