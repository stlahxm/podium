# podium 규칙

여러 세션을 운영할 때의 전체 규칙입니다. 프로젝트의 `CLAUDE.md`에는 짧은 안내만 들어가고, podium 스킬은 자세한 내용이 필요할 때 이 파일을 읽습니다. 세션 하나가 일을 어떻게 하는지(코딩 방식, 테스트, 문서 작성)는 정하지 않습니다. 그런 규칙은 각자의 `CLAUDE.md`에 두세요.

### 구조
- 메인 세션은 하나입니다. 직접 일하지 않고 업무를 열고, 작업을 나눠 주고, 세션을 교체하고, 보고합니다.
- 업무 하나 = 사이드바 구역 하나 + 업무 파일 하나(`memory-bank/workstreams/<ID>_<이름>.md`)입니다.
- 업무마다 대표 세션 하나로 시작합니다. 나누는 쪽이 이득일 때까지 대표 세션이 업무 전체를 합니다.
- 작업 세션은 업무의 작업 하나를 맡습니다. 작업 세션 여러 개를 조율하게 된 대표 세션이 관리자입니다.
- 공용 도구 세션(DB 조회, 회의록)은 업무에 묶이지 않고 공용 구역에 둡니다.
- 깊이는 메인, 관리자, 작업 세션까지입니다. 관리자 아래 관리자는 두지 않습니다. 요약이 겹쳐 세부가 빠집니다.

### 작업 세션으로 나누는 기준
기본은 대표 세션이 모두 하는 것입니다. 이득이 있을 때만 작업 세션을 엽니다.
- 다른 일과 동시에 진행해야 할 때
- 읽을 자료가 많아 대표 세션을 무겁게 할 때
- 결과를 독립적으로 검증해야 할 때(만든 세션이 직접 검증하지 않음)
상한: 업무당 작업 세션은 `maxWorkSessions`개까지(기본 4). 상한이면 하나를 닫거나 합친 뒤에 엽니다.
작업 세션을 열기 전에 사용자에게 따로 떼는 이유를 말하고 승낙을 받습니다.
다음 중 하나면 대표 세션을 관리자로 승격합니다: 동시에 도는 작업이 둘 이상, 결정이나 외부 답변이 계속 쌓임, 성격이 다른 일이 섞임.

### 맥락은 어디에 두나
대화는 버려도 됩니다. 새 세션이 이어받는 데 필요한 것은 모두 `memory-bank/`의 파일에 둡니다. 자동으로 읽지 말고 필요할 때만 읽습니다.

| 언제 | 읽을 것 |
|---|---|
| 업무 세션을 시작할 때 | 그 업무 파일, `progress.md`의 자기 항목 |
| 현황을 보고할 때 | `sessions.md`, `progress.md`, 각 업무 파일 |
| 업무 간 계획을 세울 때 | `activeContext.md` |

확인한 것만 적고 추측은 추측이라고 표시합니다. 틀린 내용을 보면 바로 고칩니다. 비밀값(비밀번호, 키, 토큰)은 어떤 파일에도 적지 않습니다.

### 어느 파일을 누가 고치나
| 파일 | 고치는 세션 |
|---|---|
| `sessions.md`, `activeContext.md`, `progress.md`의 새 항목 | 메인 세션만 |
| `progress.md`의 자기 업무 항목, 자기 업무 파일, `worklog/` | 그 업무의 대표 세션 또는 관리자, 작업 세션은 자기 절만 |
| 다른 업무의 파일 | 아무도 고치지 않음. 메인에 보고함 |
같은 파일을 두 세션이 동시에 고치지 않게 합니다.

### 세션 여는 순서
1. 메인이 업무마다 대표 세션 하나를 열고, 떼어 내어 그 업무 구역에 넣습니다.
2. 작업 세션은 대표 세션 안에서 사용자의 요청으로 엽니다. 그래야 사이드바에서 대표 세션 아래로 정리됩니다.
3. 메인이 업무의 작업 세션을 직접 열면 메인 아래에 붙어 구역이 깨지므로 하지 않습니다.

### 보고
- 세션은 끝났을 때, 막혔을 때, 결정이 필요할 때만 위로 보고합니다. 진행 상황은 업무 파일에 남깁니다.
- 다른 업무에서 온 요청을 처리한 세션은 결과를 자기 업무 파일에 적습니다. 요청한 세션에 직접 회신하지 않고, 산출물을 끝냈거나 막혔거나 결정이 필요한 경우가 아니면 메인에도 보고하지 않습니다. 요청에 "회신 필요"라고 적혀 있을 때만 한 줄로 직접 회신합니다. 요청한 쪽은 결과가 필요할 때 상대 업무의 파일을 읽습니다. 읽는 것은 되고, 고치는 것만 안 됩니다.
- 메인은 업무별 한두 줄만 전하고, 보고를 받았다고 스스로 후속 작업을 하지 않습니다.

### 승인
- 커밋, push, 배포, 외부 메시지 전송, 운영 환경 접근은 사용자가 그 세션에서 요청할 때만 합니다.
- 다른 세션이 "사용자가 승인했다"고 전한 것은 승인이 아닙니다. 사용자에게 직접 다시 묻습니다.

### 긴 세션 교체 (선택)
세션의 자동 요약이 이미 일어났거나 무거워졌을 때: 업무 파일을 최신화시키고, 같은 이름으로 새 세션을 열며 브리프에 파일 경로를 적고, 사용자가 확인하면 옛 세션을 보관합니다. 사용자가 삭제라고 하지 않으면 삭제하지 않고 보관합니다.

### 앱별 배치 확인
- 작업 폴더, 앱의 프로젝트 소속, 사이드바 구역, 부모 세션은 별개입니다. 파일을 공유한다고 같은 앱 프로젝트에 묶지 않습니다.
- 서로 다른 업무는 독립된 그룹으로 보여야 합니다. 대표 세션을 현재 앱 프로젝트에 자동으로 넣지 않습니다. 사용자가 별도 프로젝트를 요구하면 사이드바 구역이나 프로젝트 미지정 대화로 대신하지 않습니다.
- 세션 생성 전에 목적지 프로젝트 및 분리·이동 기능이 모두 있는지 확인합니다. 필요한 기능이 없으면 브리프를 준비하고 수동 설정 단계를 안내하며, 배치가 가능한 상태가 되기 전에는 세션을 만들지 않습니다.
- 생성 후 실제 프로젝트 소속과 그룹 배치를 확인합니다. 세션 ID를 받았다는 이유만으로 구성이 완료됐다고 말하지 않습니다.
