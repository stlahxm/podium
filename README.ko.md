# podium

<p align="center"><a href="README.md">English</a> | <b>한국어</b></p>

![podium: 지휘대 위의 펭귄 지휘자가 지휘봉을 들고, 펭귄 무리 위로 작은 세션 카드들이 떠 있는 모습](docs/assets/banner.png)

**버전 0.2.3, 초기 단계.** 실제 세션에서 시험한 것: 프로젝트 설정, 새 업무, 현황, 종료. 아직 전체 흐름을 검증하지 못한 것: 업무 분할, 긴 세션 교체, 많은 세션 정리. 새 프로젝트 규칙 업데이트 절차는 구조·manifest 검사를 통과했지만 실제 대화에서 시험하지 않았습니다. 자세한 내용: [docs/design-notes.md](docs/design-notes.md).

## 이게 뭔가요?

podium은 Claude Code 세션이 한 줄로 쌓이는 것을 막아 주는 플러그인입니다.
하고 싶은 일을 평소 말투로 Claude에게 말하면, podium이 그 일을 업무 하나로 만듭니다. 사이드바 구역 하나, 지금 상황을 담은 파일 하나, 대표 세션 하나입니다. 업무가 커지면 대표 세션이 작업 세션을 거느리고, 작으면 세션 하나로 끝냅니다.
상태는 대화가 아니라 파일에 있어서, 어떤 세션을 닫아도 새 세션이 멈춘 곳에서 이어받습니다.

![정리 전후: 왼쪽은 흩어진 펭귄과 엉킨 세션 카드, 오른쪽은 같은 펭귄들이 지휘대 위 펭귄 지휘자 아래 세 무리로 정돈된 모습](docs/assets/concept.png)

### 알아 둘 말 몇 가지

| 말 | 뜻 |
|---|---|
| 업무(workstream) | 세션 하나로 끝나지 않는 일 하나. 예: "할 일 앱에 알림 기능 붙이기". 사이드바 구역 하나와 파일 하나가 생깁니다. |
| 대표 세션(lead session) | 업무의 첫 세션. 나누는 이득이 생길 때까지 업무 전체를 맡습니다. |
| 작업 세션(task session) | 업무의 작업 하나를 맡는 세션. 작업 세션 여럿을 조율하는 대표 세션을 관리자(manager)라고 부릅니다. |
| 메인 세션 | 가장 먼저 말을 거는 세션 하나. 일을 직접 하지 않고 업무를 열고, 작업을 나눠 주고, 보고합니다. |
| `memory-bank/` | 상태를 담는 마크다운 파일 폴더. 무엇을 끝냈고, 다음은 무엇이고, 무엇을 정했는지 적습니다. 새 세션은 옛 대화 대신 이 파일을 읽습니다. |

### 이렇게 보입니다

사이드바에 업무마다 구역이 하나씩 생기고, 파일은 프로젝트 안에 놓입니다.

```text
사이드바                      프로젝트
-------                      --------
공용 도구                     memory-bank/
  main                         activeContext.md     업무 전체의 현재 상황
알림 기능                      progress.md          업무마다 한 줄
  reminders-lead               sessions.md          열린 세션과 교체된 세션
로그인 버그                     workstreams/
  login-bug                      W-01_reminders.md  목표, 상태, 다음 할 일, 결정
                                 W-02_login-bug.md
                               worklog/             끝난 작업 기록, 파일 하나씩
```

채워진 전체 예시는 [examples/dev-notification](examples/dev-notification/README.ko.md)(소프트웨어 기능)과 [examples/moving-plan](examples/moving-plan/README.ko.md)(코딩이 아닌 일)에 있습니다.

## 누구를 위한 건가요?

- Claude Code를 주로 데스크톱 앱에서 쓰고, 한 번에 여러 일을 하며, 사이드바가 비슷한 제목의 긴 목록이 된 분
- 일이 코드만이 아닌 분. 예시에 코딩이 아닌 업무(이사 준비)도 있습니다.
- 직접 운전하고 싶은 분. podium은 무언가를 만들거나 옮기기 전에 먼저 묻습니다.

한 번에 일 하나만 하거나, 에이전트가 알아서 돌기를 원한다면 맞지 않습니다. 그런 도구는 따로 있고, podium은 반대로 사람이 운영합니다.

## 처음 5분

1. 아래 방법으로 설치합니다.
2. 프로젝트에서 "podium 설정하고 세션 정리해 줘"라고 말합니다. podium이 세션과 문서를 읽고 묶는 방법을 보여 준 뒤 "진행 / 수정 / 파일과 규칙만 설치"를 묻습니다.
3. 여러 세션에 걸칠 일이 생기면 "이걸 새 업무로 만들어 줘: 할 일 앱에 알림 기능 붙이기"라고 말합니다. 잊어버려도 큰 일이 보이면 Claude가 한 번 제안합니다. 작은 일은 평소 대화로 처리합니다.
4. podium이 알려 준 자료를 읽고, 최대 세 가지를 묻고, 계획(구역 이름, 대표 세션, 나중에 추가할 수 있는 작업 세션)을 보여 줍니다. "진행 / 수정 / 작게 시작" 중에서 고릅니다.
5. 만들어진 대표 세션에서 일합니다. 작업 세션은 나누는 이득이 있을 때만 대표 세션 안에서 요청합니다.
6. 일이 끝나면 끝났다고 말합니다. podium이 파일을 확인한 뒤에 세션을 보관합니다.

## 필요한 것

- 플러그인을 지원하는 Claude Code(`claude plugin` 명령이 있는 버전).
- 전체 기능을 쓰려면 Claude 데스크톱 앱이 필요합니다. 세션을 만들고 사이드바 구역에 넣는 일은 앱의 세션 도구를 씁니다. 일반 터미널에서는 파일과 규칙은 설치해 주고 붙여 넣을 브리프를 만들어 주지만, 세션은 직접 열어야 합니다.

## 설치

터미널에서:

```bash
claude plugin marketplace add stlahxm/podium
claude plugin install podium@podium
```

마켓플레이스는 `main`의 최신 개발 파일 대신 태그와 커밋으로 고정한 배포본을 설치합니다. GitHub Release만 생성해도 이 지정이 바뀌지는 않습니다. 배포 절차는 [버전 배포](docs/releasing.ko.md)를 보세요.

기존 설치를 업데이트하려면:

```bash
claude plugin marketplace update podium
claude plugin update podium@podium
```

업데이트에는 새 플러그인 버전이 필요합니다. 자동 업데이트는 선택 사항이며 사용자가 `/plugin` → Marketplaces에서 켭니다.

플러그인을 업데이트해도 프로젝트에 이미 복사한 규칙은 바뀌지 않습니다. v0.2.0부터 podium에 규칙 비교와 승인받을 패치 준비를 요청할 수 있습니다. 스킬이 안내하는 절차이며 자동 마이그레이션 서비스는 아닙니다. [프로젝트 규칙 업데이트](docs/updating.ko.md)를 보세요.

한 세션에서만 써 보려면 저장소를 복제한 뒤 `claude --plugin-dir ./podium`을 씁니다.
데스크톱 앱에서는 마켓플레이스를 추가한 뒤 프롬프트 옆 **+** 버튼에서 **Add plugins**를 고릅니다.

## 들어 있는 것

- 스킬 `podium` 하나와 절차 열 개가 있습니다: 프로젝트 설정, 플러그인·프로젝트 규칙 업데이트, 업무 시작, 현황, 분할·승격, 종료, 끝난 세션 한번에 정리, 지난 결정 찾기, 별도 세션으로 끝난 일 검증, 긴 세션 교체. 외울 명령은 없고 "이걸 새 업무로 만들어 줘", "podium 업데이트해 줘", "지금 상황 어때?", "이 업무 닫아 줘", "끝난 세션 정리해 줘", "캐시 방식은 어디서 정했더라?" 같은 평소 문장으로 요청합니다.
- 맥락을 담는 파일 템플릿(`memory-bank/`)과 프로젝트 모든 세션이 podium의 존재를 알게 하는 짧은 `CLAUDE.md` 규칙 절(영어 기준 약 370단어: 역할, 나누기, 파일 담당, 보고와 승인)(영어, 한국어). 전체 규칙은 [docs/rules.ko.md](docs/rules.ko.md)에 있습니다
- 공용 도구 세션(읽기 전용 데이터 조회 등)의 규칙 템플릿(`templates/ko/tool-session.md`)
- `examples/`의 가상 예시 둘: 소프트웨어 기능 하나와 이사

## 비용은 어떻게 낮추나

매 턴 컨텍스트에 들어가는 것은 스킬의 한 줄 설명뿐입니다. 절차와 템플릿은 필요할 때만 읽습니다. 이 한 줄도 싫다면 수동 모드를 켭니다. `skills/podium/SKILL.md`의 머리말(파일 맨 위 설정 블록)에 `disable-model-invocation: true`를 추가하고, 필요할 때 `/podium`으로 부릅니다.

## 설정

`memory-bank/.podium.json`: `idPrefix`(기본 `W`), `ledgerPath`(기본 `memory-bank/sessions.md`), `maxWorkSessions`(기본 4). [docs/config.md](docs/config.md)를 보세요.

## 한계

- 세션은 그 세션에서 사용자가 직접 요청해야 새 세션을 열 수 있고, 떼어 내기(사이드바에서 부모 아래에서 꺼내기)는 연 세션만 할 수 있습니다. podium은 업무마다 대표 세션을 먼저 열고, 나누는 일은 그 안에서 하게 하는 방식으로 이를 피합니다.
- podium은 세션이 일을 어떻게 하는지(코딩 방식, 테스트, 글쓰기)는 정하지 않습니다. 그런 규칙은 각자의 `CLAUDE.md`에 두세요.
- 실제 세션에서 확인한 것([docs/design-notes.md](docs/design-notes.md) 참고): 스킬이 맞는 절차만 읽고, 작은 질문에는 조용하고, 답을 기다리며, 사용자가 직접 입력했을 때 대표 세션을 열고 구역에 넣을 수 있습니다. 아직 확인하지 못한 것: 분할, 긴 세션 교체, 세션 정리, 세션이 이미 많은 프로젝트.

## 비슷한 프로젝트

- [Gas Town](https://github.com/gastownhall/gastown)과 [CCPM](https://github.com/automazeio/ccpm)은 코딩 에이전트를 자동으로 조율합니다.
- [claude-workstream-kit](https://github.com/ChristopherA/claude-workstream-kit)은 프로젝트 하나의 업무 상태를 파일로 관리합니다.
- podium은 여러 종류의 일에 걸쳐 많은 세션을 운영하는 사람을 위한 것이고, 단계마다 사람이 결정합니다.

자세한 내용과 출처는 [docs/design-notes.md](docs/design-notes.md)에 있습니다.

## 기여하기

누구의 기여든 환영합니다. 대부분의 변경은 문장을 고치는 일이라 코드를 짤 필요가 없습니다.

처음 기여하기 좋은 일:
- 실제 세션에서 podium을 써 보고 결과를 알려 주세요(무엇을 입력했고 어떻게 동작했는지). 아직 시험하지 못한 절차(분할, 긴 세션 교체, 세션 정리)의 결과가 가장 도움이 됩니다.
- 절차, 템플릿, 문서를 개선해 주세요. 영어와 한국어 파일은 함께 고칩니다. 방법은 [CONTRIBUTING.ko.md](CONTRIBUTING.ko.md)에 있습니다.
- 아직 없는 종류의 일로 예시를 추가해 주세요(지어낸 내용이어야 합니다).
- 두 언어 어느 쪽이든 문장을 다듬어 주세요.

큰 변경은 먼저 [이슈](https://github.com/stlahxm/podium/issues)로 방향을 맞춰 주세요. 작은 수정은 바로 풀 리퀘스트를 보내셔도 됩니다.

참여하는 모든 분은 [행동 강령](CODE_OF_CONDUCT.ko.md)을 따릅니다. 보안 문제는 공개 이슈가 아니라 [SECURITY.md](SECURITY.md)의 방법으로 알려 주세요.
